# chamfer_v2 角部补丁尝试：一次未完成的修复

> 日期：2026-10-03。
> 起点：上一轮把 `chamfer_v2` 的壳不闭合定位到"缺少 8 个角部面"，并留下判据"修完去掉两处 `#[ignore]`"。
> 结论：**角部面做出来了（18 → 26 面），但壳仍然不闭合。生产代码未改动，本文与配套测试是这次尝试的全部留存。**
> 所有数字均由 `crates/operations/tests/chamfer_v2_measurements.rs` 断言，改动即转红。

---

## 1. 起点与判据

上一轮的结论是：`chamfer_v2` 从不调用 `corner::compute_corners`，而 `fillet_builder` 调用（`fillet_builder.rs:183`），所以三条倒角棱交汇的 8 个角完全没有任何面来封。倒角立方体应为 6 侧面 + 12 斜面 + **8 个角三角形** = 26 面，而实测只有 18 个全四边形。

配套的两处 `#[ignore]` 判据：

- `chamfer_shell_manifold.rs`：每条边被恰好 2 个面引用，且结果单连通
- `chamfer_corner_patches.rs::walking_engine_builds_the_corner_patches`：面数 26、8 个三角面

本轮的指令是"接 `corner::compute_corners`，修完去掉那两处 `#[ignore]`"。

## 2. 第一条路：直接复用 fillet 的角部模块 —— 否决

`corner::compute_corners` 签名与 fillet 调用完全一致（同一个 `&[Stripe]`），看起来可以直接复用。实测接入后：

| 指标 | 接入前 | 接入 `compute_corners` 后 |
|---|---|---|
| F | 18 | **26** ✓ |
| 面类型 | 18 平面 | 18 平面 + **8 NURBS** |
| free 边 | 72 / 72 | **96 / 96** ✗ |
| components | 18 | **26** ✗ |

面数达标了，壳反而更碎。原因是两种角是**不同的几何**：

- `corner.rs` 把 3 条以上 stripe 的顶点路由到 `spherical_triangle`，该模块文档写明是 "rolling-ball sphere"、"great-circle arcs"、"Fillet radius"
- chamfer 的角是**平面三角形**，球面补丁的边界弧落不到相邻面那条直的接触线上
- 它还依赖 `CircSection`，而 `analytic.rs::try_analytic_chamfer` 的注释本身就写着 "`CircSection` is shaped for fillets"，chamfer 只是把弦长的一半塞进去凑合描述 chord

**结论**：角部面必须由 chamfer 专用代码构造，且必须是**平面**。

## 3. 第二条路：平面角部补丁 —— 面数达标，壳仍不闭合

新建 `crates/blend/src/chamfer_corner.rs`，从已存在的边里 adopt 角三角的三条边，构造一个平面三角形。结果：

| 指标 | HEAD（现状） | 接平面角补丁后 | 正确值 |
|---|---|---|---|
| F | 18 | **26** ✓ | 26 |
| 角面 | 0 | **8 个平面三角** ✓ | 8 |
| over-shared | 0 | 0 ✓ | 0 |
| E | 72 | 80 | 48 |
| **free 边** | 72 | **64** ✗ | 0 |
| **components** | 18 | **12** ✗ | 1 |
| V | 76 | 76 | 24 |

面数预算达成，`over-shared` 为 0（没有重复引用），但**壳没有闭合**。

### 3.1 实现中被实测纠正的三个错误假设

写这个模块时我连错了三次，全部靠打印实测顶点纠正，而非推理：

1. **角点邻接度是 4，不是 3。** 直觉上"三条棱交汇 = 三个邻居"。实测 `(0,0,1)` 的邻居是 `(0,1,0)`、`(1,0,0)`、`(10,0,1)`、`(0,10,1)` —— 两个同角伙伴 + 两个邻角点。

2. **不能"取最近 2 个邻居"。** 按距离排序取前 N，会把侧面的角也选中：侧面角 `(9,1,0)` 的两个近邻距离是 8（整条棱长），而真角是 1.41。第一版按"度 == 3"过滤，一个角都建不出来（0 个）；改成"最近 2 个"后建出 32 个（8 个真角 + 24 个侧面角）。

   最终判据是**距离跳变**：真角的距离列表是 `1.41, 1.41, 10, 10`（小簇后面有跳变），侧面角是 `8, 8, 1, 1`（跳变在前面）。这个判据实测给出 8 个。

3. **去重键要用三点集合。** 每个角会被它的 3 个接触点各发现一次，但每次看到的"近邻对"不同，所以按单点去重无效（48 → 23 → 32）。按排序后的三元组去重才正确。

## 4. 为什么壳仍不闭合：顶点从未焊接

上面那张表里真正的线索不是 F，是 **V**。

倒角立方体应有 V = 24（12 条棱 × 2 个接触点）。实测 **V = 76**，两种状态下都是 76。欧拉示性数 `V - E + F` 分别是 22 和 22，而闭合亏 genus-0 壳必须是 2。

**根因**：倒角装配的三个生产者（trimmer 造接触边、stripe 造斜面、角部造角面）各自新建顶点实体，实体几何重合但 `VertexId` 不同，因此没有任何一条边被两个面共享 —— `free` 永远到不了 0。

这也解释了为什么 `sew::weld_faces` 在这里无效：它按焊接后的端点对合并边，而实测 72 条边的 72 个引用里，去重后的端点对也是 72 个（量化到 1e-6），**没有任何一对重复可供合并**。在角补丁存在之后也实测接了 `weld_faces`，`free` 仍是 64。

### 4.1 一处被实测推翻的说法

分析中途我曾断言"侧面应该是八边形，四个角没被切掉"。**这是错的。** 实测 `z=0` 侧面的四个顶点是 `(1,1,0)`、`(9,1,0)`、`(1,9,0)`、`(9,9,0)` —— 正确的正方形。倒角切的是侧面的四条**边**，不是四个**角**，所以侧面本来就该是四边形。侧面是对的。

同样被推翻的还有"对照组是拓扑上的黄金参考"：控制引擎 `operations::chamfer::chamfer` 虽然 `free = 0`、通过 `validate_shell_closed`，但它自己的 `V = 32`（应为 24）、`V - E + F = 10`（应为 2）。**在本代码库里"闭合"意味着每条边被引用两次，不意味着欧拉示性数成立。**

## 6. 结论与下一步

**已完成**：8 个角部平面三角面，面数预算达成（18 → 26），`over-shared = 0`。角部几何的判据（三点集合去重、距离跳变找角、adopt 而非 mint 三条已存在的边）已确立并有测试固化。

**未完成**：壳仍不闭合，`free = 64`、`components = 12`。根因是顶点从未焊接（V=76 vs 应为 24），需要在 `analytic.rs` / `builder_utils.rs` / `trimmer.rs` 之间让装配共用顶点实体——这是一轮独立的接口重构，不是加面能解决的。

**为什么没有提交生产代码**：修复未完成，提交一个 `free=64` 的壳比不提交更糟——下游会拿到一个面数正确、拓扑损坏的结果，比明显的坏结果更难发现。
